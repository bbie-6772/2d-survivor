# 0014. Growth 폴더를 신설한다

- 날짜: 2026-09-04 (D8)
- 상태: 채택
- 변경 대상: `conventions.md` 2항

## 맥락

경험치 드랍을 구현하며 `HeartSpawner`가 들어갈 자리가 없었다.

- `Core/`는 0002에서 **"특정 오브젝트에 종속되지 않는 게임 규칙"** 으로 조건을 달아뒀고,
  `HeartSpawner`는 심장 프리팹 전용이므로 이 조건을 통과하지 못한다.
- `Enemy/`는 0002가 이미 기각한 논리(분류 기준이 **진영이 아니라 기능**)에 걸린다.

`Level/`을 검토했으나 기각했다. 게임 개발에서 level은 스테이지/맵을 먼저 뜻하며
(`LoadLevel`, level design, Level Editor) 성장 축을 가리키는 이름으로는 오독을 만든다.
또한 그 폴더에 들어갈 셋(드랍 생성 · 접촉 수집 · 경험치 누적) 중 레벨업은 **마지막 단계 하나**뿐이라
나머지 둘이 들어갈 자리처럼 보이지 않는다. 컨벤션 6항의 "이름만 보고 책임을 말할 수 있는가"는
파일뿐 아니라 폴더에도 적용된다.

## 결정

`Assets/_Project/Scripts/Growth/` 를 만든다.

> `Growth/` 에는 **경험치 획득부터 레벨업 발행까지의 흐름**을 둔다.
> 스탯 값의 **소유와 적용**은 각 소유자(`Player/`, `Weapon/`)에 남긴다.

D8 시점 구성:

```
Growth/
  HeartSpawner.cs      # 심장 프리팹을 지정 위치에 생성/회수한다 (SpawnerBase 자식)
  (예정) 심장 픽업     # 심장에 붙어 플레이어 접촉 시 경험치를 준다
  (예정) 경험치 누적   # 경험치를 누적하고 임계값에서 레벨업을 발행한다
```

## 이유

조건을 처음에 "플레이어가 강해지는 과정에 **관여하는** 코드"로 잡았더니 거의 모든 것이 통과했다.
넓은 조건은 0002가 `Core/`에서 인지한 잡동사니 위험을 그대로 재현한다.

그래서 후보 넷을 실제로 판정해 **하나를 탈락시키는 것**으로 조건을 확정했다.

| 후보 | 판정 |
|---|---|
| 심장 픽업(접촉 시 경험치 지급) | 통과 |
| 경험치 누적 / 레벨업 발행 | 통과 |
| **레벨업 시 올라가는 스탯 값 자체** | **탈락** |
| 약 제조(공격속도 상승) | 보류 — 재검토 시점 참조 |

세 번째가 탈락하는 근거가 조건 문장을 결정했다. `_moveSpeed`는 `PlayerMovement`의 **상태**이고
컨벤션 1항(`public` 필드 금지)에 따라 밖에서 만질 수 없다. 따라서 `Growth/`의 코드가 할 수 있는 것은
**"올려달라고 요청"** 까지이고, 실제 값과 그 적용은 소유자에 남는다.
폴더가 갈리는 것이 아니라 **책임이 갈리는** 것이다.

이 조건이 없으면 `Growth/`가 `PlayerMovement`의 내부 값을 만지는 코드를 품게 되고,
"폴더가 다른 폴더의 내부를 만진다"는 형태가 된다.

## 대가 (인지하고 있음)

- `Growth/`가 세 파일로 시작해 작다. 폴더 하나가 파일 셋을 위해 생긴 셈이다.
- 스탯 강화 선택(기획서상 3종 택 1)의 UI가 어디로 갈지는 아직 정하지 않았다.
  선택 UI는 강화 대상을 알아야 하므로 `Growth/`와 `UI/` 사이에서 갈린다.

## 재검토 시점

스탯 강화 선택(3종 택 1) 구현 시. 그 UI의 소속이 위 조건 문장의 다음 시험이다.
약 제조 시스템도 같은 시점에 함께 판정한다.
