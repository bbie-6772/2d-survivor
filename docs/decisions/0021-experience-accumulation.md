# 0021. 경험치는 정수로 누적하고, 요구치는 수식으로 가변화한다

- 날짜: 2026-09-05 (D9)
- 상태: 채택
- 관련: 0020(심장 획득), `plan.md` 축 4

## 맥락

`HeartCollector`가 넘긴 획득량을 받아 레벨업을 판정할 곳이 필요했다.
`GameTimer` → `GameEnder` → `GameEndScreen`에서 만든
"발행자 / 판정자 / 표시자" 구조를 성장 쪽에도 그대로 적용한다.

```
Heart.Collect() → HeartCollector → PlayerExperience.Add()
                                        ↓ OnLevelUp
                                  [선택지 진행 담당]
                                        ↓ 고른 카드
                                PlayerUpgradeApplier.Apply()
```

`PlayerExperience`는 **레벨업이 일어났다**까지만 안다.
어떤 선택지가 뜨는지, 무엇이 선택됐는지, 스탯이 얼마나 오르는지 전혀 모른다.

## 결정

### 정수 사용

`Heart._value`, `PlayerExperience.Current`, `_requiredExp` 모두 `int`.

심장 하나가 1점이고 요구치가 정수 단위라 소수점이 나올 자리가 없다.
`float`를 허용하면 부동소수점 누적 오차로 "4.9999점인데 레벨업이 안 되는" 상황을
스스로 초대하게 된다.

단, **UI에서 진행률을 그릴 때 정수 나눗셈에 주의한다.**
`Current / _requiredExp`를 `int`끼리 나누면 3/5가 0이 된다.
한쪽을 `float`로 승격해야 하며, 그 변환을 `PlayerExperience`가 프로퍼티로
내보낼지 UI가 직접 할지는 UI 구현 시 결정한다.
기준은 **UI가 `Current`와 `_requiredExp`를 둘 다 알아야 하는가**이다.

### 이월과 다중 레벨업

넘친 경험치는 버리지 않고 이월하며, `while`로 다중 레벨업을 계산한다.
보스 드랍처럼 `_value`가 큰 심장이 들어올 여지를 미리 막는다.

`Mathf.Max(..., 0)` 같은 하한 방어는 넣지 않는다.
루프 조건이 `Current >= _requiredExp`이므로 뺀 결과가 음수일 수 없고,
음수가 나온다면 그것은 **로직이 깨졌다는 신호**인데 `Max`가 그것을 0으로 덮어 숨긴다.
`Health`가 `Mathf.Max`를 쓰는 것은 외부에서 임의의 `amount`가 들어오기 때문이며
상황이 다르다.

### 발화 순서

```csharp
Current -= _requiredExp;      // 상태 확정
OnLevelUp?.Invoke();          // 그 다음 발화
_requiredExp *= _growthRate;
```

`Health.TakeDamage`가 `_alreadyDead = true`를 `OnDied?.Invoke()`보다 먼저 두는 것과
같은 원칙이다. **구독자가 깨어나는 시점에 발행자가 일관된 상태여야 한다.**
발화가 앞서면 구독 UI가 차감 전 값을 그린다.

### 요구치 가변화 — 수식, SO 아님

`_requiredExp *= _growthRate`로 레벨업마다 요구치를 키운다. **SO는 도입하지 않는다.**

SO가 값을 하는 지점은 **레벨별 요구치를 손으로 하나하나 정하고 싶을 때**다.
수식으로 충분하면 SO는 파일만 늘린다. 그리고 5분 루프를 한 번도 돌려보지 않은
시점에 데이터 컨테이너부터 만드는 것은 순서가 거꾸로다.

`plan.md` 축 4(데이터 주도)는 웨이브 테이블과 `UpgradeCard`에서 이미 증명된다.

## 미해결 (D9 부채) — 다중 레벨업 큐

`while`이 여러 바퀴 돌면 `OnLevelUp`이 **한 프레임에 여러 번 발화한다.**
구독자가 `timeScale = 0`으로 멈추고 카드 3장을 띄우는 코드라면,
두 번째 발화가 첫 번째 UI를 덮어 플레이어가 레벨을 잃는다.

**이것은 예외 상황이 아니라 평범한 플레이에서 발생한다.**
`OnTriggerEnter2D`는 같은 프레임에 여러 콜라이더에 대해 각각 호출되므로,
심장이 몰려 있는 곳을 지나가면 그대로 재현된다.
실제 테스트에서 한 프레임에 3회 발화를 확인했다.

해결 방향은 **되돌아오는 신호**다. 선택 UI가 "선택이 끝났다"를 알리고,
그것을 듣는 쪽이 대기 중인 레벨업이 남았는지 보고 다음을 띄운다.
`async`/`await`이나 코루틴 폴링 없이 이미 쓰고 있는 이벤트만으로 성립한다.

**큐를 누가 소유하는가는 선택 UI 구현 시 결정한다.**
`PlayerExperience`가 들면 "경험치를 센다"는 책임에 진행 관리가 섞이므로,
컨벤션 6항 기준으로는 선택지 진행 담당 쪽이 유력하다.

현재 코드에는 `levelUpCount` 지역변수가 이 목적을 위해 남아 있다.

## 재검토 시점

웨이브 테이블 완성 후 5분 루프를 실제로 돌려본 시점.
`_growthRate`(현재 2)가 곱셈으로 적절한지, 손으로 잡아야 할 곡선이면
그때 SO를 붙인다.
