# 0017. 마감 전 주말 작업 범위를 재조정한다

- 날짜: 2026-09-05 (D9)
- 상태: 채택
- 관련: `plan.md` 기술 축, `spec.md` 「만들지 않을 것」 확장

## 맥락

현재 준비중인 이력서 제출 마감까지, 남은 실작업 시간이 별로 남지 않았다.
이 시점에 코어루프가 닫혀 있지 않았다. 타이머도 승패 판정도 재시작도 없어, 게임이 시작도 끝도 없는 상태였다.

`plan.md`가 정한 기술 축 중 증거로 남는 방식이 서로 다르다는 점이 판단의 기준이 되었다.

| 축 | 증거가 남는 방식 |
|---|---|
| 2 — FSM 리팩토링 | 커밋 로그(`refactor`) |
| 3 — 오브젝트 풀링 | **Profiler 수치 (숫자로 남는 유일한 축)** |
| 4 — 데이터 주도 | SO 에셋 파일 |
| 5 — 이벤트 기반 UI 분리 | 참조 방향 |

## 결정

### 잘라낸 것

**무기 교체(샷건 / 스나이퍼).**
`spec.md`의 성장 선택지 중 무기 교체 항목을 이번 구현 범위에서 뒤로 미루고,
레벨업 선택지를 스탯 강화만으로 채운다.
투사체와 관통은 각각 새 시스템이며, 투사체는 풀링 대상이 하나 늘고
관통은 히트 기록 관리가 붙는다. 스탯만으로도 코어루프는 완결된다.

**애니메이션 도입.**
당초 계획은 "애니메이션을 넣어보며 한계점을 찾고 FSM을 도입한다"였으나,
FSM이 필요하다는 근거는 이미 코드 안에 있다.
`PlayerMovement`가 대시를 `_dashInput` 플래그와 `_dashCooldownRemaining` 타이머로
처리하는데, `spec.md`가 요구하는 **대시 무적(0.2~0.3s)이 아직 없다.**
그것을 추가하면 플래그가 하나 더 늘어 조합이 곱으로 증가한다.
이쪽이 애니메이터 스테이트와 코드 스테이트를 동기화하는 작업보다 싸고,
리팩토링의 근거로도 정직하다.

### 추가한 것

**승리 조건 잠정 처리.**
보스(중간 / 최종)를 이번 범위에서 제외하는 이상 `spec.md`의 승리 조건을
충족할 수 없다. 메인 타이머 5분 만료를 **생존 승리**로 잠정 처리해 루프를 닫는다.
보스 구현 시 이 조건은 "최종보스 격파"로 교체된다.

## 이유

축 3만이 숫자로 남는다. 따라서 시간이 부족해질 때 마지막까지 지켜야 하는 것은
풀링이고, 먼저 포기할 수 있는 것은 FSM이다.

작업 순서는 **리스크가 낮고 짧은 것부터** 배치해, 어느 시점에 손을 놓아도
제출 가능한 상태가 유지되도록 했다.

1. 타이머 + 승패 확정 + 재시작 (코어루프를 닫는다)
2. 성장 시스템 (심장 → 경험치 → 선택지 3장)
3. 웨이브 테이블 SO 이관
4. Profiler 측정 → `v0.1-before-pooling` 태그 → 풀링 → 재측정
5. (여유 시) 대시 무적 + FSM 리팩토링

## 대가

- `spec.md`의 BossPhase 상태와 보스 광폭화 기획이 코드에 대응물 없이 남는다.
  기획서와 구현의 괴리를 문서로 명시하지 않으면 읽는 쪽이 미구현을 누락으로 오해한다.
- 승리 조건이 "5분 생존"이므로 난이도 곡선의 종착점이 없다.
  웨이브 테이블 설계 시 5분 지점을 최고 밀도로 잡아 보완한다.

## 재검토 시점

마감 이후. 포트폴리오를 계속 발전시킬 경우 보스가 첫 복구 대상
