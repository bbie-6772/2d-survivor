# 0023. 공격 주기를 `_attacksPerSecond`로 뒤집고, `WaitForSeconds` 부채를 청구한다

- 날짜: 2026-09-05 (D9)
- 상태: 채택
- 관련: **0008의 대가 항목 해소**, 0016(웨이브 구현 시 택한다고 미뤘던 선택), 0022(스탯 소유)

## 맥락

0008은 타이밍을 코루틴으로 처리하며 `WaitForSeconds`를 필드에 캐싱했고,
그 대가로 **"간격을 런타임에 바꿔도 반영되지 않는다"** 를 남겼다.
0016은 그 청구 시점을 "웨이브 구현 시"로 미뤘다.

공격속도 업그레이드 카드가 그보다 먼저 도달했다.

동시에 값의 방향 문제가 드러났다. `_interval`은 **작아져야 강해지는** 값이라,
`UpgradeCard.Amount`에 `0.9`를 적게 된다. 다른 카드는 전부 가산(`+5`)인데
이 카드만 배수이며, 에셋만 보면 "공격속도 0.9 증가"로 읽힌다.

## 결정

### 값을 뒤집는다

`_interval`(초/회) → `_attacksPerSecond`(회/초).

모든 카드가 **"올라가면 강해진다"** 로 통일되고, `Amount`도 가산으로 일관된다.
`Upgrade_AttackSpeed.asset`은 `0.9` 대신 `+0.3`(초당 1회 → 1.3회)이 된다.

대기 시간이 필요한 지점에서만 `1f / _attacksPerSecond`로 역수를 취한다.
`_attacksPerSecond <= 0f`는 `Awake`에서 검증한다. 역수를 취하기 **전에** 막지 않으면
`Infinity`가 `WaitForSeconds`로 들어가고, 음수는 대기가 0으로 처리되어
**매 프레임 공격**이 된다. 후자가 조용히 이상해지는 쪽이라 더 나쁘다.

### `_wait`을 재생성한다 (A안)

```csharp
_attacksPerSecond += amount;
_wait = new WaitForSeconds(1f / _attacksPerSecond);
```

후보 셋 중 A를 택했다.

| 후보 | 반영 시점 | 대가 |
|---|---|---|
| **A. `_wait` 재생성** | **다음 바퀴부터 (최대 1주기 지연)** | **지연** |
| B. 코루틴 중단 후 재시작 | 즉시 | 공격 주기가 리셋된다. 레벨업이 잦을수록 공격이 **느려지는** 역설 |
| C. `WaitForSeconds` 폐기, `Time.time` 비교로 전환 | 즉시 | `AttackLoop` 전면 재작성, 매 프레임 도는 코루틴 |

## 이유

**B는 게임플레이가 손해를 본다.** 0.9초를 기다린 직후 카드를 먹으면 그 시간이 버려진다.
그리고 0016이 정리한 코루틴 정지 문제를 다시 안는다.

**C가 구조적으로는 더 옳다.** `_attacksPerSecond`를 매 바퀴 다시 읽으므로
캐싱 문제가 근본적으로 사라지고, `Time.time`은 `timeScale`의 영향을 받아
정지 중 자동으로 멈춘다(0019와 맞물린다).

그럼에도 지금 하지 않는 이유는 **축 3의 정직성**이다.
매 프레임 도는 코루틴이 동시 300마리 상황에서 어떤 비용인지는
D6에 Profiler를 켜봐야 안다. 측정 전에 미리 바꾸면 before/after 비교 대상이 흐려진다.

A의 지연은 최대 한 주기(현재 1초)이며 체감되지 않는다.
`timeScale = 0` 중에는 `WaitForSeconds`도 멈추므로, 카드 선택 후 재개되는 프레임의
잔여 대기는 여전히 옛 간격 기준이다. 이 역시 한 주기 이내다.

## 대가

- 대기 중인 코루틴은 여전히 옛 `WaitForSeconds` 객체를 붙잡고 있다.
  **값 변경이 즉시 반영되지 않는다**는 성질이 코드에 남는다.
- 공격속도가 누적되면 간격이 프레임에 근접한다(초당 20회 = 0.05초).
  그때 `Physics2D.OverlapCircleAll`이 **매 호출 배열을 새로 할당**하므로
  GC 압력이 공격속도에 비례해 증가한다.
  → **D6 측정 항목에 추가한다.** 축 3의 소재가 하나 늘었다.

## 재검토 시점

D6 Profiler 측정 직후. `OverlapCircleAll`의 할당이 실제로 유의미하면
`ContactFilter2D` + `List<Collider2D>` 오버로드로 전환하고,
같은 자리에서 C안(`Time.time` 전환)도 함께 판단한다.
