# 0009. 씬 상주 오브젝트 참조는 인스펙터로 꽂는다

- 날짜: 2026-08-30 (D3)
- 상태: 채택
- 관련: D2 부채 4번 해소

## 맥락

D2의 `EnemyChase`는 좀비마다 `FindAnyObjectByType<PlayerMovement>()`로 플레이어를 찾았다.
씬 전체를 뒤지는 함수이므로 마릿수만큼 늘어나며, 300마리 기획에서 그대로 둘 수 없었다.

D3에서 `EnemySpawner`를 만들며 같은 코드를 스포너에 옮겨 쓸 뻔했고, 그 시점에 재검토했다.

## 결정

- 씬에 미리 존재하는 오브젝트 간 참조는 **`[SerializeField]` + 인스펙터 드래그**로 연결한다.
- 런타임 생성 객체(좀비)에 필요한 참조는 **스포너가 `Setup`에서 주입**한다.
- `EnemyChase._target`은 `Start` 자체 탐색이 아니라 `Init(Transform)` 주입으로 받는다.
- 스포너의 추적 대상 필드 타입은 **`Transform`**으로 한다.

## 이유

### 인스펙터 참조를 택한 근거는 성능이 아니다

`Start`에서 1회 호출하는 비용은 무시할 수준이다. D2의 문제는 함수 자체가 아니라 **300회 반복**이었다.
실질 이득은 셋이다.

- 실행 **전에** 연결이 보장되고 씬을 열면 눈으로 확인된다
- 타입이 아니라 **개체**를 특정한다 (`FindAnyObjectByType`은 이름 그대로 "아무거나 하나")
- 대상 교체가 드래그로 끝난다

제약은 스포너 개수가 아니라 **"언제 존재하느냐"** 다. 런타임 생성 객체, 프리팹에 저장되는 씬 참조,
다른 씬의 오브젝트는 인스펙터로 연결할 수 없다. 그 경우에만 코드 탐색이나 주입을 쓴다.

### `Transform`을 택한 근거

구체 타입(`PlayerMovement`)은 인스펙터에 잘못된 오브젝트를 꽂을 수 없다는 이점이 있으나,
스포너가 "플레이어의 이동 로직"을 알게 되어 의존이 실제 필요(위치)보다 넓어진다.

결정적인 것은 **스폰 중심이 반드시 플레이어일 필요가 없다**는 점이다.
카메라 기준, 맵의 특정 지점, 보스 위치를 중심으로 하는 웨이브가 나올 수 있고,
`Transform`이면 코드를 고치지 않고 드래그만으로 바뀐다.
필드 이름을 `_player`가 아니라 `_target`으로 지은 시점에 이미 답이 나와 있었다.

## 함께 강제되는 것

인스펙터 참조는 사람이 드래그를 깜빡할 수 있으므로 **null 가드가 필수**다.
`_prefab`(base `Awake`), 스포너 `_target`(`OnInit`), 카메라 `_target`(`Awake`)에 각각 적용했다.
방식은 `Debug.LogError(메시지, this)` + `enabled = false`로 통일한다.
두 번째 인자에 `this`를 넘기면 콘솔 클릭 시 Hierarchy에서 해당 오브젝트가 선택된다.

## 대가 (인지하고 있음)

- 스포너가 늘면 같은 대상을 여러 번 드래그해야 한다. 프리팹화하면 씬 참조가 저장되지 않으므로
  스포너를 런타임 생성하는 설계로 가면 이 결정을 재검토해야 한다.
- `enabled = false`가 막지 못하는 경로가 있다(0006 대가 항목, 0008 코루틴).

## 재검토 시점

웨이브 매니저가 스포너를 런타임 생성하게 되는 시점.
