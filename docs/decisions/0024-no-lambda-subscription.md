# 0024. 해제해야 하는 이벤트 구독은 람다로 붙이지 않는다

- 날짜: 2026-09-05 (D9)
- 상태: 채택
- 관련: `conventions.md` 5항 개정 (0005 / 0013에 이은 세 번째 개정)

## 맥락

레벨업 검증 중 디버그 구독을 이렇게 붙였다.

```csharp
_experience.OnLevelUp += () => Debug.Log("레벨업 성공!");
```

이 람다는 호출될 때마다 **새 delegate 객체**로 만들어진다.
`-=`로 떼려고 글자까지 똑같은 코드를 써도 다른 객체이므로 지워지지 않는다.
`Delegate.Remove`가 invocation list에서 항목을 찾을 때 참조를 비교하기 때문이다.

디버그 한 줄에서는 실해가 없다. 문제는 이 습관이 다른 자리로 옮겨갈 때다.

## 결정

> **떼야 하는 구독은 람다로 붙이지 않는다.**
> 명명된 메서드를 쓰거나, 람다가 필요하면 delegate를 필드에 담아 그 필드로 붙였다 뗀다.

## 이유

**D6 풀링에서 즉시 터진다.**

`EnemyDeath`와 `DamageFlash`는 `OnEnable`에서 구독하고 `OnDisable`에서 해제하는
대칭 구조다. 풀링은 같은 오브젝트를 껐다 켜며 재사용하므로 이 쌍이 반복 실행된다.

여기서 람다를 쓰면 **`OnDisable`의 해제가 아무것도 지우지 않는다.**
재사용할 때마다 invocation list에 구독이 하나씩 쌓이고,
`event`는 같은 핸들러가 여러 번 등록되면 **여러 번 호출한다.**
좀비를 100번 재사용하면 피격 처리가 100번 돈다.

에러도 예외도 없다. 데미지 숫자만 조용히 틀린다.
0016이 "조용히 틀리는 종류의 버그"라고 부른 계열이며,
그중에서도 **재사용 횟수에 비례해 증상이 커지므로 초기 테스트에서 발견되지 않는다.**

## 함께 정리된 것 — `event` 구독의 성질

| 성질 | 내용 |
|---|---|
| 실행 순서 | 구독한 순서대로 앞에서부터. **구현 동작이지 계약이 아니다.** 순서에 의존하는 코드를 쓰지 않는다 |
| 중복 구독 | `+=` 두 번 → 리스트에 두 개. **두 번 호출된다** |
| `-=` | 일치하는 항목 중 **마지막 하나만** 제거 |
| 미구독 해제 | 예외 없이 조용히 통과 |
| 자료구조 | stack이 아니라 순서 있는 불변 리스트. `+=`는 `Delegate.Combine`으로 **새 리스트를 만들어 대입** |

핸들러 실행 순서가 중요해지는 순간, 그것은 이벤트가 아니라
명시적 호출 순서를 가진 다른 구조여야 한다는 신호다.

## 검증 방법

같은 메서드를 `+=` 두 번 하고 발화하면 로그가 두 줄 찍힌다.
`-=` 한 번 후 다시 발화하면 한 줄이 남는다.
이 실험 하나로 "리스트인가 집합인가"와 "제거가 몇 개를 지우는가"가 동시에 확인된다.

## 재검토 시점

없음. 이 규칙에 예외를 둘 이유가 확인되지 않았다.
