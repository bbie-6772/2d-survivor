# 0029. 공격 연출은 무기에서 분리하고, 이펙트는 판정 범위를 재현하지 않는다

- 날짜: 2026-09-05 (D9)
- 상태: 채택
- 관련: 0017(애니메이션 제외), 0016(코루틴 정지 수단), 0028(사건/상태 이벤트 분리)

## 맥락

0017에서 애니메이션을 범위 밖으로 잘라냈으나, 공격이 나가도 화면에 아무 변화가 없어
타격감이 전혀 없었다. 애니메이터를 도입하지 않으면서 "공격이 발동했다"를
전달할 수단이 필요했다.

`MeleeWeapon.Update`가 이미 `Debug.DrawRay`로 부채꼴을 그리고 있으나
Scene 뷰에서만 보인다.

## 결정

### 연출은 별도 컴포넌트가 소유한다

`MeleeWeapon`에 `OnAttacked` 이벤트를 두고 `AttackFlash`가 구독한다.

`MeleeWeapon`이 스프라이트를 직접 참조하면 공격 로직이 연출까지 소유하게 된다.
`DamageFlash`가 `Health.OnDamaged`를 구독하는 구조와 같은 형태로 맞췄고,
0028에서 정한 "사건 이벤트"의 두 번째 사례다.

발화 위치는 `AttackLoop`의 `foreach` **밖**이다.
맞은 대상이 있든 없든 휘두른 것은 사실이다.

### 코루틴은 재시작(retrigger) 방식

```csharp
if (_flashRoutine != null) { StopCoroutine(_flashRoutine); }
_flashRoutine = StartCoroutine(FlashRoutine());
```

"도는 중이면 무시"로 두면, 공격속도 카드로 주기가 `_duration`보다 짧아졌을 때
**이펙트가 켜진 채 유지되고 이후 공격이 씹힌다.** 눈에는 그럴듯하나
실제 공격 타이밍과 어긋난다.

`StopCoroutine`에 핸들이 필요해 `Coroutine` 필드를 보관한다(0016의 실사용처).

> **주의: `StopCoroutine`으로 끊으면 코루틴 뒷부분의 정리 코드가 실행되지 않는다.**
> 현재는 다음 줄에서 곧바로 `enabled = true`로 켜므로 문제가 없으나,
> 정리가 필요한 코루틴을 끊을 때 흔히 놓치는 지점이다.

### 회전은 pivot 계층으로 처리

```
Player
 └ AttackPivot     ← Transform 참조. 조준 방향으로 회전
    └ Circle       ← SpriteRenderer 참조. 켜고 끄기
```

스프라이트를 직접 회전시키면 **자기 중심(pivot)에서 제자리 회전**한다.
플레이어를 중심으로 돌게 하려면 부모를 회전시켜야 한다.

참조를 두 개(`Transform _pivot`, `SpriteRenderer _flashSprite`) 두는 이유는
역할이 다르기 때문이다. **어디를 향하는가**와 **보일지 말지**.
`_flashSprite.transform.parent`로 접근하면 참조가 하나로 줄지만
계층 구조에 의존하게 되어 오브젝트를 옮기면 조용히 깨진다.

`Vector2` 방향을 각도로 바꾸는 변환은 `Mathf.Atan2(y, x) * Mathf.Rad2Deg`.
`Atan2`는 라디안을 반환하고 `Quaternion.Euler`는 도를 받는다.
`Atan(y/x)`와 달리 4사분면을 구분하며 x가 0일 때도 안전하다.

### 크기 갱신은 `Flash` 시점에

공격 범위가 카드로 커지므로(`MeleeWeapon.Range`) 이펙트도 따라가야 한다.

0028의 "드물게 변하면 이벤트" 기준상 `OnRangeChanged`를 두는 것이 맞아 보이나,
**`Flash`가 어차피 회전을 갱신하고 있으므로 같은 자리에서 스케일도 갱신하면
추가 비용이 사실상 0이다.** 이벤트를 하나 늘릴 이유가 없다.
회전과 스케일 모두 "이펙트를 현재 상태에 맞춘다"는 하나의 일이라 응집도도 맞는다.

## 이펙트는 판정 범위를 재현하지 않는다

원형 스프라이트를 눌러 타원으로 만들어 90도 부채꼴을 흉내 내려 했으나 실패했다.
**부채꼴은 앞으로 갈수록 벌어지는 형태이고 타원은 가운데가 가장 넓다.**
모양이 근본적으로 다르므로 어떤 스케일 조합으로도 일치하지 않는다.

크기를 범위에 맞추자 타원이 화면 상당 부분을 덮어 **좀비가 가려졌다.**
알파를 낮추는 것은 해법이 아니다. 0.1초짜리 연출을 옅게 만들면 아예 안 보인다.

> **짧게 번쩍이는 연출은 작고 진하게. 크고 옅게가 아니다.**
> 큰 도형은 옅어도 시야를 방해하고, 작은 도형은 진해도 거슬리지 않는다.

따라서 이펙트는 `Range * 0.6` 수준으로 축소해 **"공격이 나갔다"는 신호만 전달**하고,
판정 범위 표현은 포기한다. 판정의 정확한 시각화가 필요해지면
90도 부채꼴 PNG를 만들어 **스프라이트만 교체**하면 되며 코드 변경은 없다.

## 대가

- 화면에 보이는 이펙트와 실제 판정 범위가 일치하지 않는다.
  플레이어가 이펙트를 보고 사거리를 가늠할 수 없다.
- `timeScale = 0`(레벨업 창) 중에 `WaitForSeconds`가 멈추므로
  이펙트가 켜진 채 얼어붙을 수 있다. 지속 시간이 0.1초라 발생 확률이 낮고,
  발생해도 카드 선택 중 잔상이 남는 정도다.
  필요해지면 `WaitForSecondsRealtime`으로 교체한다(0019 참조).

## 재검토 시점

부채꼴 스프라이트를 확보했을 때. 그 시점에 이펙트가 판정 범위를 정확히
표현하도록 스케일 계수를 다시 맞춘다.
