# 0003. IDamageable 인터페이스를 도입한다

- 날짜: 2026-08-29 (D2)
- 상태: 채택

## 맥락

`Health`가 유일한 구현체인 시점에서 인터페이스를 만드는 것은
투기적 추상화(speculative abstraction)가 될 수 있다. 실제로 D2 작업 중
"왜 만들었지"라는 의문이 한 번 나왔고, `public` 접근 제한자 누락으로 컴파일 에러도 한 번 났다.

## 결정

`IDamageable { void TakeDamage(float amount); }` 를 도입한다.
`Health`가 이를 구현한다.

## 이유

**"나중에 쓸지도 모르니까"가 아니다.** 기획서에 무기 3종(몽둥이·샷건·스나이퍼)이
확정되어 있고, 인터페이스가 없으면 그 셋이 각각 `GetComponent<Health>()`를 부른다.
`Health`의 시그니처가 바뀌면 손댈 곳이 셋이 된다.

즉 근거는 **때리는 쪽이 맞는 쪽의 구체 타입을 몰라도 되게 하는 것**이며,
이는 미래 가정이 아니라 이미 확정된 사실에 근거한다.

또한 호출부가 늘어난 뒤 인터페이스를 끼워 넣는 비용(세 파일 수정)이
지금 넣고 나중에 지우는 비용(두 파일)보다 크다.

## 범위

- `Heal`은 인터페이스에 넣지 않는다. 때리는 쪽이 회복을 알 이유가 없다.
  인터페이스는 "호출하는 쪽이 필요로 하는 계약"이지 클래스의 기능 목록이 아니다.
- 자기 컴포넌트를 참조할 때(`PlayerHitReceiver` → 자신의 `Health`)는
  구체 타입으로 직접 잡는다. 인터페이스는 낯선 상대를 때릴 때 값을 한다.

## 재검토 시점

D8에서 무기 3종이 잘려나가고 몽둥이 하나로 끝난다면, 이 인터페이스는 제거 대상이다.
