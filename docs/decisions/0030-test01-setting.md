### 2차 까지의 결론

병목은 Physics2D(66%), GC Alloc은 무의미, 풀링의 원래 근거는 기각,
현재 이 테스트를 통해 수정해야 할 방향은 좀비 수 제어로 확정.

**1·2차 표의 AliveCount가 마지막 지점 외에 비어 있는 이유:**
이 시점에는 좀비 수를 표시하는 UI(`CountZombieText`)가 아직 없었다.
마리 수를 알 방법이 Hierarchy를 세는 것뿐이라 지점별 기록이 불가능했다.
"몇 마리일 때 몇 ms"를 말할 수 없다는 것이 3차를 다시 돌린 이유이며,
`AliveCount` 프로퍼티와 표시 UI는 그 필요 때문에 만들어졌다.

**충돌 OFF는 채택하지 않는다.**
2차에서 CPU가 2.17ms로 떨어졌으나, 같은 조건에서 AliveCount가 267에서 평형에 도달했다.
좀비가 서로 겹치면서 근접 무기 사거리 안에 훨씬 많이 들어와 처치율이 스폰율을 따라잡은 것이다.
즉 2차의 개선은 **성능 최적화가 아니라 게임 규칙 변경의 결과**다.
2132마리와 267마리를 비교한 셈이므로 1차와 직접 비교할 수 없고,
겹치지 않는 편이 게임성에 맞다고 판단해 원복했다.

### 3차: 충돌 ON, AliveCount 동반 측정 (한계점 탐색)

#### 관찰

- **임계는 682~753 사이.** 100마리 증가에 프레임 타임 5배(2.32ms → 11.41ms).
  마리 수에 대해 선형이 아니다.
- 임계 이후 비용의 62~64%가 `FixedUpdate.Physics2DFixedUpdate`.
  1차(2132마리, 66.2%)와 같은 항목이다.
- 화면 관찰: 3:40까지 좀비가 흩어져 있고, 3:35부터 한 덩어리로 뭉친다.
  **변수는 마리 수가 아니라 밀집도**로 보인다. 같은 수라도 흩어지면 싸고 뭉치면 비싸다.
- 3:45(603, 1.99ms)가 3:50(513, 2.80ms)보다 빠르다.
  단일 프레임 측정이라 튄 값일 가능성이 있어 신뢰도 낮음.

#### 결론

- 안전 상한: **600**. 682는 임계에 너무 근접해 여유가 없다.
- **거리 기반 회수는 기각한다.** 처음에는 "화면 밖에 뭉친 좀비를 회수하면
  마리 수와 밀집도가 함께 내려간다"고 보았으나, Scene 뷰로 실제 분포를 확인하니
  좀비는 멀리 흩어진 것이 아니라 **플레이어를 향해 반원형으로 정체**하고 있었다.
  스폰 지점이 플레이어 기준 원이므로 전부 한 점으로 수렴하며,
  회수할 만큼 멀어진 개체가 없다. 스폰 위치를 어떻게 분산해도 결국 같은 밀집이 생긴다.
- 따라서 **동시 스폰 상한**을 채택한다.

> 682에서 2.32ms, 753에서 11.41ms이므로 여유를 두고 600으로 상한을 결정

### 4차: 동시 스폰 상한 600 적용 후

조건: 1차 웨이브에서 600에 도달하도록 조정 / 2:50 시점 / 상한 도달 상태

| 항목 | 값 |
|---|---|
| AliveCount | 600 (상한 도달) |
| CPU | 8.10ms (에디터 오버헤드 포함) |
| PlayerLoop | 75.0% (6.07ms) |
| UpdateScene | 5.41ms |
| FixedUpdate.Physics2DFixedUpdate | 4.01ms (49.6%) |
| FixedUpdate.ScriptRunBehaviour | 0.96ms (11.8%) |
| GC Alloc | 0 B |
| Batches / Triangles / Vertices | 9 / 1.27k / 1.59k |

상한이 걸린 **최악의 경우**에도 60fps 예산(16.6ms) 안에 들어온다.
상한 없이 같은 부하 구간까지 누적했을 때가 16.01ms(1차)였으므로 약 2배 개선이다.
물리 비중은 여전히 절반이나, 마리 수가 임계(682) 아래로 고정되어 예산 내에 머문다.

### 5차: 정상 플레이 (측정용 세팅 전부 원복)

무적·무조작을 해제하고 실제 플레이 조건에서 확인했다.

| 조건 | 결과 | AliveCount |
|---|---|---|
| 밸런스 조정 전 | 40초 시점 사망 | 65 |
| 밸런스 조정 후(레벨업 경험치 배수 2.0 → 1.2) | 평형 유지 | 최대 30 |

**상한 600은 정상 플레이에서 발동하지 않는다.**
실제 부하는 임계(682)의 10% 미만이며, 상한은 최악의 경우를 막는 안전장치로만 존재한다.
성능 병목은 정상 플레이 조건에서 나타나지 않는다는 뜻이다.
