# 0012. 카메라 추적은 LateUpdate + SmoothDamp로 한다

- 날짜: 2026-08-30 (D3)
- 상태: 채택

## 맥락

기획서에 "플레이어는 카메라 중앙에 고정"이라 되어 있으나, 완전 고정과 부드러운 추적 중
어느 쪽을 뜻하는지는 명시되지 않았다. 스폰 위치가 "화면 밖"으로 정의되어 있어
카메라가 플레이어를 따라오지 않으면 화면 밖이 어디인지 자체가 검증되지 않는다.

## 결정

- 갱신 시점: **`LateUpdate`**
- 보간: **`Vector2.SmoothDamp`** (`_smoothTime` 기본 0.2)
- z: `Awake`에서 1회 캐싱해 고정
- 스크립트는 Main Camera에 직접 붙인다

## 이유

### `LateUpdate`

프레임 내 순서는 `FixedUpdate`(물리 주기) → `Update` → 코루틴 재개 → **`LateUpdate`** → 렌더링이다.
플레이어가 `Rigidbody2D`로 움직이므로 `Update`에서 따라가면 아직 이동이 반영되지 않은 프레임이 섞여
한 프레임씩 뒤처지고, 이는 **떨림**으로 보인다. `LateUpdate`는 모든 이동이 끝난 뒤 렌더링 직전에 돈다.

### `SmoothDamp`

`Lerp` + `Time.deltaTime` 조합은 프레임레이트에 따라 결과가 미묘하게 달라진다.
`SmoothDamp`는 스프링-댐퍼 모델이라 더 안정적이다.

`ref currentVelocity`는 **함수가 채우는 내부 상태**다. 호출 사이에 상태를 이어주는 통로이므로
반드시 필드여야 한다. 지역변수로 두면 매 프레임 0으로 초기화되어 "지금 멈춰 있다"고 판단하고
매번 처음부터 가속하는 뚝뚝 끊긴 움직임이 된다. 손으로 대입하지 않는다.

### z 고정

2D 카메라는 z가 음수(보통 -10)여야 한다. 플레이어 위치를 그대로 대입하면 z가 0이 되어 아무것도 보이지 않는다.
z는 변하지 않는 값이므로 매 프레임 계산에 넣을 이유가 없고, `Awake`에서 1회 캐싱하면
`Vector3`가 아닌 **`Vector2`로 보간**할 수 있어 계산 차원이 하나 줄어든다.

`transform.position.z = _z`는 `CS1612`로 막힌다. 프로퍼티가 돌려주는 `Vector3`는 **struct 복사본**이므로
고쳐도 원본에 반영되지 않고, 컴파일러가 무의미한 코드로 판단해 차단한다.
`Vector3`가 class였다면 컴파일은 되고 아무 일도 안 일어나는 버그가 되었을 것이다.
→ **프로퍼티는 통째로만 대입한다.**

### 카메라에 직접 붙이는 이유

`transform`이 곧 카메라이므로 코드가 짧고, 컨벤션 5항의 "`Camera.main`을 Update에서 호출하지 않는다"
문제 자체가 발생하지 않는다.

## 대가 (인지하고 있음)

- 부드러운 추적이므로 플레이어가 화면 정중앙에서 미세하게 벗어난다. 기획서 문구와 엄밀히는 다르다.
- 스프라이트가 픽셀 단위로 떨리는 별도 문제(Pixel Perfect)는 아직 다루지 않았다.
- 스폰 반경(`_spawnRadius = 20`)이 하드코딩이다. `orthographicSize`와 `aspect`로 계산하면
  해상도 변화에 대응하지만, 현재는 인스펙터에서 눈으로 맞추는 편이 검증이 빠르다.

## 재검토 시점

보스전 연출(화면 흔들림, 줌)이 들어가는 시점. 그때 카메라 제어 주체가 하나 이상이 되므로
현재의 "카메라가 스스로 따라간다" 구조를 재검토한다.
