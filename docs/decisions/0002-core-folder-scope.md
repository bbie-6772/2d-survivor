# 0002. Core 폴더의 범위를 "게임 규칙 전반"으로 넓힌다

- 날짜: 2026-08-29 (D2)
- 상태: 채택
- 변경 대상: `conventions.md` 2항

## 맥락

컨벤션 2항은 `Core/`를 "GameState, 타이머, 이벤트"로 정의했다.
D2에서 만든 `Health`, `IDamageable`, `ContactDamage` 세 개가 이 정의에 들어가지 않는데,
그렇다고 `Player/`나 `Enemy/`에 두기에는 양쪽이 공유한다.

`Utils/`도 후보였으나 기각했다. `Utils/`는 이 게임이 아니어도 그대로 쓸 수 있는 코드
(벡터 헬퍼, 확장 메서드)를 위한 자리다. 체력은 "0이 되면 죽는다"는 이 게임의 규칙이므로
도메인 코드다.

## 결정

`Core/`를 **"특정 오브젝트에 종속되지 않는 게임 규칙"** 으로 정의한다.
`Health`, `IDamageable`, `ContactDamage`를 여기에 둔다.

## 이유

- 컨벤션 2항은 타입별이 아닌 **기능별** 분류를 채택했다. `Interfaces/` 같은 폴더를 만들지 않기로 한
  이상, 인터페이스는 사용처 옆에 둬야 하고 그 자리가 `Core/`다.
- `ContactDamage`는 좀비와 보스만 붙이므로 `Enemy/`도 후보였다.
  기각한 이유는 폴더 분류 기준이 **진영이 아니라 기능**이기 때문이다.
  함정이나 환경 데미지가 생기면 `Enemy/`에서 가져다 쓰는 어색함이 생긴다.

## 대가

`Core/`가 잡동사니 폴더가 될 위험이 있다. "특정 오브젝트에 종속되지 않는"이라는
조건을 매번 확인하고, 해당 안 되면 기능별 폴더로 보낸다.

## 재검토 시점

`Core/` 파일이 10개를 넘으면 하위 분류(예: `Core/Combat/`)를 검토한다.
