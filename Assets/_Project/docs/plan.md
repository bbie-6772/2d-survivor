# 프로젝트 개요

AI를 이용한 바이브코딩으로만 게임을 제작했던 경험에서, 역할을 바꿔 보려한다!  
역량강화를 위한 프로젝트 설계를 도와주는 AI 기획과 직접적인 코드 생성없이 조언만 해주는 멘토 AI를 적극 활용한다.
마감 기한은 1~2주 이내로 간단하게 진행할 예정이다.

---

## 증명할 기술 축 (AI 제안)

| 순위 | 기술 축 | 왜 증명하나 | 예상 질문 |
|---|---|---|---|
| 1 | Update / FixedUpdate 분리한 자체 이동 컨트롤러 (가속·감속 곡선, 대각선 입력 정규화, 프레임 독립성) | 프레임 단위 실행 흐름의 이해가 여기서 드러남 | "왜 입력은 Update, 이동은 FixedUpdate인가?" |
| 2 | FSM — 플레이어(Normal / Dashing / Cooldown)와 적. enum switch로 시작해 인터페이스 기반으로 리팩토링 | 리팩토링 *흔적* 자체가 실력의 증거 | "왜 중간에 구조를 바꿨나?" |
| 3 | Object Pool + per-frame GC alloc 제거, Profiler 수치 before/after | 유일하게 **숫자로 남는** 축 | "얼마나 개선됐나?" |
| 4 | ScriptableObject 데이터 주도 설계 (적·무기 스탯, 웨이브 테이블) | 하드코딩과 데이터의 경계를 아는지 | "밸런스 수정에 재빌드가 필요한가?" |
| 5 | 이벤트 기반 UI 분리 | 결합도 감각 | "HUD가 Player를 직접 참조하면 뭐가 문제인가?" |
| 6 | 세이브/로드, Addressables | 시간이 남으면. **버려도 되는 것** | — |

### 추천 장르

- 웨이브 기반 탑다운 서바이버 : 적 수백 마리 스폰 → 성능이 자연스럽게 무너진다 → 3번 축이 억지 없이 생김. 데이터 주도(적/무기 SO)도 필연.

- 액션 플랫포머 한 스테이지 : 캐릭터 컨트롤러를 직접 짜면 coyote time, jump buffer, 접지 판정 같은 "게임 느낌" 구현력이 드러남.
